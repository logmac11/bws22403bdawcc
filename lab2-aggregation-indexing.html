🔄 What is the Aggregation Pipeline?

The MongoDB Aggregation Framework processes data records through a multi-stage pipeline. Each stage transforms the data, and the output of one stage becomes the input for the next.

📚
SQL Equivalent: Similar to SELECT ... GROUP BY ... HAVING ... ORDER BY, but more flexible and capable of handling nested documents, arrays, and complex transformations.

🏗️ Pipeline Architecture

db.collection.aggregate([ { $match: { ... } }, // Stage 1: Filter documents { $group: { ... } }, // Stage 2: Group & calculate { $sort: { ... } }, // Stage 3: Order results { $project: { ... } } // Stage 4: Reshape output ])
🔍 Key Rules:
  • Stages execute in order (top to bottom)
  • Place $match early to reduce data volume
  • Each stage outputs a stream of documents to the next stage
  • Results can be saved to a new collection using $out or $merge

📊 Step 1: Basic Aggregation ($match, $group, $sort)

We'll analyze CampusMart pricing trends and category performance.

📌 Task 1: Average Price by Category

use campusmart db.products.aggregate([ { $match: { inStock: true } }, { $group: { _id: "$category", avgPrice: { $avg: "$price" }, totalItems: { $sum: 1 }, maxPrice: { $max: "$price" } }}, { $sort: { avgPrice: -1 } } ])
🔍 Stage Breakdown:
  • $match: Filters only in-stock products (reduces processing load)
  • $group: Groups by category, calculates avg/sum/max
  • $sort: Orders results by average price (highest first)
  • _id: "$category": The $ references the field value
✅ Expected Output:
[ { _id: 'Electronics', avgPrice: 128.33, totalItems: 3, maxPrice: 180 }, { _id: 'Textbooks', avgPrice: 55, totalItems: 3, maxPrice: 65 }, { _id: 'Appliances', avgPrice: 45, totalItems: 1, maxPrice: 45 } ]

📌 Task 2: Seller Performance Metrics

db.products.aggregate([ { $group: { _id: "$seller.name", avgRating: { $avg: "$seller.rating" }, productCount: { $sum: 1 }, totalValue: { $sum: "$price" } }}, { $match: { avgRating: { $gte: 4.7 } } }, { $sort: { avgRating: -1 } } ])

🔍 Step 2: Advanced Pipeline ($project, $unwind, $limit)

Reshape data, deconstruct arrays, and control output size.

📌 Task 3: Reshape & Limit Output

db.products.aggregate([ { $match: { category: "Textbooks" } }, { $project: { _id: 0, title: "$name", priceMYR: "$price", currency: "$currency", yearPublished: "$specs.year" }}, { $sort: { priceMYR: 1 } }, { $limit: 2 } ])
🔍 New Operators:
  • $project: Renames fields, excludes _id, extracts nested values
  • $limit: Restricts output to N documents (saves memory)
  • Field references use "$fieldName" syntax

📌 Task 4: Unwind Tags Array

db.products.aggregate([ { $unwind: "$tags" }, { $group: { _id: "$tags", count: { $sum: 1 } }}, { $sort: { count: -1 } }, { $limit: 5 } ])
✅ Expected Output: Top 5 most common tags across all products.

⚡ Step 3: Indexing & Performance Tuning

Indexes speed up queries by avoiding full collection scans. Critical for big data workloads.

📊 Before Indexing: Check Execution Plan

db.products.find({ category: "Textbooks", price: { $gt: 50 } }).explain("executionStats")
🔍 Look for:
  • "stage": "COLLSCAN" → Full collection scan (slow)
  • "totalDocsExamined" vs "nReturned" → High ratio = inefficient
  • "executionTimeMillis" → Query duration

🚀 Create Compound Index

db.products.createIndex({ category: 1, price: 1 }, { name: "category_price_idx" })
🔍 Index Syntax:
  • 1 = Ascending, -1 = Descending
  • Compound indexes support queries on prefix fields
  • name option helps identify indexes later

📈 After Indexing: Verify Performance Gain

db.products.find({ category: "Textbooks", price: { $gt: 50 } }).explain("executionStats")
✅ Success Indicators:
  • "stage": "IXSCAN" (Index Scan) instead of COLLSCAN
  • "totalDocsExamined" ≈ "nReturned"
  • "executionTimeMillis" drops significantly

📤 Step 4: Export Aggregation Results

Save pipeline outputs to a new collection, then export to JSON for external analytics (Power BI, Python, Excel).

📦 Save Results to New Collection

db.products.aggregate([ { $group: { _id: "$category", avgPrice: { $avg: "$price" }, totalItems: { $sum: 1 } }}, { $out: "category_analytics" } ], { allowDiskUse: true })
🔍 $out Stage:
  • Creates/replaces category_analytics collection
  • allowDiskUse: true permits large pipeline operations
  • Must be the final stage in the pipeline

💾 Export to JSON File

Exit mongosh (exit) and run in PowerShell:

mongoexport --uri "mongodb://student:uthm2026@localhost:27017/campusmart" ` --collection category_analytics ` --out category_analytics.json
✅ Expected: connected to: mongodb://... exported: 3 records

🛠️ Troubleshooting & Tips

❌ "Pipeline stage $out must be the last stage"

$out or $merge must be the final stage. Move any $sort, $limit, or $project before it.

❌ "Exceeded memory limit for $group"

Add { allowDiskUse: true } to the aggregate options, or place $match earlier to reduce data volume.

db.collection.aggregate([...], { allowDiskUse: true })
❌ Index not being used (still COLLSCAN)

1. Verify query matches index prefix exactly
2. Check field types match index (String vs Number)
3. Run db.products.getIndexes() to confirm index exists
4. Use .explain("executionStats") to debug

❌ mongoexport: File already exists

Delete or rename the existing file, or use a new filename:
--out category_analytics_v2.json
