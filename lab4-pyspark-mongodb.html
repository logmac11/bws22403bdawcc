🔌 Step 2: Connect & Read from MongoDB

Initialize SparkSession with the MongoDB connector, then load CampusMart data into a distributed DataFrame.

from pyspark.sql import SparkSession # Initialize Spark with MongoDB connector spark = SparkSession.builder \ .appName("CampusMart-Analytics") \ .config("spark.jars.packages", "org.mongodb.spark:mongo-spark-connector_2.12:10.3.0") \ .config("spark.mongodb.input.uri", "mongodb://student:uthm2026@localhost:27017/campusmart.products") \ .getOrCreate() # Read MongoDB collection into DataFrame df = spark.read.format("mongodb").load() # Inspect schema & sample df.printSchema() df.show(5)
🔍 Key Concepts:
  • spark.jars.packages: Auto-downloads MongoDB connector at runtime
  • input.uri: Tells Spark where to read from (use Atlas URI for cloud labs)
  • df.printSchema(): Shows inferred column types
  • df.show(5): Displays first 5 rows (triggers lazy evaluation)
✅ Expected Schema Snippet:
root |-- _id: string (nullable = true) |-- name: string (nullable = true) |-- category: string (nullable = true) |-- price: double (nullable = true) |-- inStock: boolean (nullable = true) |-- seller: struct (nullable = true) | |-- name: string | |-- rating: double

⚙️ Step 3: Distributed Transformations

Apply Spark transformations to analyze pricing trends and seller performance across distributed partitions.

📌 Task 1: Category Pricing Summary

from pyspark.sql.functions import avg, count, col category_stats = df.filter(col("inStock") == True) \ .groupBy("category") \ .agg( avg("price").alias("avgPrice"), count("*").alias("productCount") ) \ .orderBy(col("avgPrice").desc()) category_stats.show()

📌 Task 2: Top Sellers by Average Rating

from pyspark.sql.functions import explode # Flatten seller array/struct if needed, then aggregate seller_ratings = df.select("seller.name", "seller.rating") \ .groupBy("name") \ .agg(avg("rating").alias("avgRating")) \ .orderBy(col("avgRating").desc()) seller_ratings.show()
🔍 Spark vs MongoDB Syntax:
  • Spark uses filter() instead of $match
  • groupBy().agg() replaces $group
  • Transformations are lazy (executed only on .show(), .collect(), or .write())

🧩 Step 5: Partitioning & Scale Concepts

Spark splits data into partitions for parallel processing. Understanding partitions is critical for big data performance.

# Check default partitions print(f"Default partitions: {df.rdd.getNumPartitions()}") # Repartition for better parallelism df_repartitioned = df.repartition("category") print(f"After repartition: {df_repartitioned.rdd.getNumPartitions()}") # Explain execution plan (physical vs logical) df_repartitioned.explain()
🔍 Partitioning Rules:
  • Default = 1 partition for small local datasets
  • repartition() shuffles data across nodes (expensive but balances load)
  • coalesce() reduces partitions without full shuffle (cheaper)
  • Cloud Spark (Databricks/Glue) auto-scales partitions based on cluster size

🛠️ Troubleshooting & Tips

❌ "Failed to find data source: mongodb"

Verify connector coordinate: org.mongodb.spark:mongo-spark-connector_2.12:10.3.0. Ensure Spark version is 3.x. Restart runtime after !pip install.

❌ "Connection refused" to MongoDB

Colab runs in Google's cloud. To connect to localhost, use ngrok or switch to MongoDB Atlas M0 URI (recommended for cloud labs).

❌ "Java heap space" or OOM errors

Filter data earlier, use .limit() for testing, or increase Colab RAM (Runtime → Change runtime type → High-RAM). In production, scale cluster nodes.

💡 How to use Atlas instead of localhost?

Replace URI with your Atlas connection string:
.config("spark.mongodb.input.uri", "mongodb+srv://student:pass@cluster.mongodb.net/campusmart.products")
