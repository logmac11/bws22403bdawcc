📦 Step 1: Local Kubernetes Cluster Setup

We'll use minikube (free, local K8s) to avoid cloud billing while learning production-grade orchestration.

# Install kubectl (K8s CLI) # Windows (winget): winget install Kubernetes.kubectl # macOS: brew install kubectl # Linux: sudo apt install kubectl # Install minikube # Download from: https://minikube.sigs.k8s.io/docs/start/ # Start local cluster minikube start --cpus=2 --memory=4096 # Verify cluster kubectl cluster-info kubectl get nodes
✅ Expected Output:
NAME STATUS ROLES AGE VERSION minikube Ready control-plane 2m v1.28.0

🚀 Step 2: Deploy a Data Processor

Create a Deployment that runs a simple Python data processing script in a container.

cat > data-processor.yaml << 'EOF' apiVersion: apps/v1 kind: Deployment meta name: campusmart-processor spec: replicas: 2 selector: matchLabels: app: data-processor template: metadata: labels: app: data-processor spec: containers: - name: processor image: python:3.10-slim command: ["python", "-c"] args: - | import time, random categories = ["Textbooks", "Electronics", "Appliances"] while True: print(f"Processing: {random.choice(categories)} | Price: {random.uniform(10,200):.2f}") time.sleep(5) resources: requests: memory: "64Mi" cpu: "100m" limits: memory: "128Mi" cpu: "250m" EOF kubectl apply -f data-processor.yaml
🔍 Deployment vs Pod:
  • Pod: Smallest deployable unit (1+ containers)
  • Deployment: Manages Pod replicas, rolling updates, self-healing
  • replicas: 2: K8s ensures 2 pods always run
  • resources: Prevents noisy neighbors in shared clusters

📈 Step 3: Scale & Expose via Services

Scale horizontally to handle load, then expose internally via a ClusterIP service.

# Scale to 5 replicas kubectl scale deployment campusmart-processor --replicas=5 # Verify scaling kubectl get pods -w # Expose internally kubectl expose deployment campusmart-processor \ --type=ClusterIP \ --name=processor-service \ --port=8080 \ --target-port=8080 kubectl get svc
💡
Why Services? Pods are ephemeral (IPs change on restart). Services provide stable DNS names & load balancing across healthy pods. In data pipelines, services route traffic to workers, brokers, or APIs.

⚙️ Step 4: Batch Processing with Kubernetes Jobs

Deployments run forever. Jobs run to completion (ideal for ETL, backfills, model training).

cat > etl-job.yaml << 'EOF' apiVersion: batch/v1 kind: Job metadata: name: campusmart-etl-batch spec: ttlSecondsAfterFinished: 100 backoffLimit: 3 template: spec: containers: - name: etl-runner image: python:3.10-slim command: ["python", "-c"] args: - | print("📥 Extracting CampusMart data...") print("🔄 Transforming & cleaning...") print("✅ Loading to analytics warehouse...") print("🎉 Job completed successfully") restartPolicy: Never EOF kubectl apply -f etl-job.yaml kubectl get jobs -w
🔍 Job Key Fields:
  • backoffLimit: 3: Retries failed pods 3 times before marking failed
  • restartPolicy: Never: Jobs don't restart completed pods
  • ttlSecondsAfterFinished: Auto-cleans completed job pods (saves cluster resources)

🔧 Step 5: Configuration & Secrets Management

Externalize environment variables using ConfigMaps & Secrets instead of hardcoding in YAML.

# Create ConfigMap kubectl create configmap processor-config \ --from-literal=LOG_LEVEL=info \ --from-literal=BATCH_SIZE=1000 # Create Secret (base64 encoded automatically) kubectl create secret generic db-credentials \ --from-literal=username=student \ --from-literal=password=uthm2026 # View (secrets are masked) kubectl get configmap processor-config -o yaml kubectl get secret db-credentials -o yaml
⚠️
Production Note: In cloud K8s, use AWS Secrets Manager / GCP Secret Manager / HashiCorp Vault instead of native K8s Secrets (which are only base64 encoded, not encrypted at rest by default).

🛠️ Troubleshooting & Tips

❌ "Pending" pods that won't start

Check resources: minikube start --cpus=4 --memory=8192. If using Docker driver, ensure Docker Desktop has allocated enough CPU/RAM. Run minikube delete && minikube start to reset.

❌ "CrashLoopBackOff"

Pod is failing repeatedly. Check logs: kubectl logs or kubectl logs job/. Fix syntax/errors in command/args, then delete & reapply.

❌ "ImagePullBackOff"

Typo in image name or private registry auth issue. For public images like python:3.10-slim, verify spelling. Run minikube ssh to test connectivity.
