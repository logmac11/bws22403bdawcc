📘 LAB 7: Infrastructure as Code (IaC) with Terraform for MongoDB Atlas

Big Data Analytics with Cloud Computing

🔒 100% Free • Declarative Provisioning, State Management & GitOps

Lab Focus: Provision a free MongoDB Atlas M0 cluster using Terraform, understand state files, detect configuration drift, and safely destroy cloud resources. Submit Terraform plan/apply outputs and state explanations.

📦 Step 1: Environment & API Setup

Terraform is a CLI tool that reads declarative config files and calls cloud APIs to create/modify infrastructure.

1Install Terraform CLI
# Windows (via Chocolatey or winget) winget install Hashicorp.Terraform # macOS brew install terraform # Linux sudo apt update && sudo apt install terraform # Verify terraform -version
2Generate MongoDB Atlas API Keys

Go to Atlas → Organization Access → API Keys → Create API Key → Assign Project Owner role → Save Public Key & Private Key.

🔒
Security Rule: Never commit API keys to GitHub. Store them in terraform.tfvars (gitignored) or environment variables.

📝 Step 2: Write Terraform Configuration

Create a new folder lab7-terraform/ and add these files:

📄 main.tf

terraform { required_providers { mongodbatlas = { source = "mongodb/mongodbatlas" version = "~> 1.15" } } } provider "mongodbatlas" { public_key = var.atlas_public_key private_key = var.atlas_private_key } resource "mongodbatlas_project" "uthm_lab" { name = "UTHM-BigData-Lab7" org_id = var.atlas_org_id } resource "mongodbatlas_cluster" "m0_free" { project_id = mongodbatlas_project.uthm_lab.id name = "lab7-m0-cluster" cluster_type = "REPLICASET" provider_name = "TENANT" provider_instance_size_name = "M0" provider_region_name = "AP_SOUTHEAST_1" }

📄 variables.tf

variable "atlas_public_key" { description = "Atlas API Public Key" } variable "atlas_private_key" { description = "Atlas API Private Key" } variable "atlas_org_id" { description = "Atlas Organization ID" }

📄 terraform.tfvars (DO NOT COMMIT)

atlas_public_key = "your_public_key_here" atlas_private_key = "your_private_key_here" atlas_org_id = "your_org_id_here"
🔍 Declarative vs Imperative:
  • You describe what you want (M0 cluster in Singapore)
  • Terraform figures out how to create it via Atlas API
  • Idempotent: Running twice yields the same result

🚀 Step 3: Plan & Apply Infrastructure

Initialize the provider, preview changes, then provision.

# 1. Initialize working directory & download provider terraform init # 2. Preview what Terraform will do (dry run) terraform plan # 3. Execute & create resources terraform apply -auto-approve
✅ Expected Plan Output:
Plan: 2 to add, 0 to change, 0 to destroy. + mongodbatlas_project.uthm_lab + mongodbatlas_cluster.m0_free
1Verify in Atlas UI

Log into MongoDB Atlas → You should see project UTHM-BigData-Lab7 with cluster lab7-m0-cluster provisioning.

📦 Step 4: State Management & Drift Detection

Terraform tracks real-world resources in a terraform.tfstate file. Never edit it manually.

# View tracked resources terraform state list # Show detailed state of cluster terraform state show mongodbatlas_cluster.m0_free # Detect drift (change cluster name in main.tf, then run) terraform plan
🔍 Why State Matters:
  • Maps config → real cloud resources
  • Enables plan to detect drift (manual UI changes vs code)
  • In teams, state is stored remotely (S3, Terraform Cloud) with locking

🗑️ Step 5: Destroy & Cleanup

Always destroy lab resources to stay within free tier limits and practice responsible cloud usage.

# Preview destruction terraform plan -destroy # Destroy all managed resources terraform destroy -auto-approve
⚠️
terraform destroy only removes resources tracked in state. Manually created Atlas resources won't be deleted. Always provision via code for full lifecycle control.

🛠️ Troubleshooting & Tips

❌ "Error: Invalid API key"

Verify keys in terraform.tfvars. Ensure API key has Project Owner role. Regenerate if expired.

❌ "Provider not installed"

Run terraform init first. Check internet connection. If behind proxy, configure HTTP_PROXY env vars.

❌ "Resource already exists"

Terraform state is out of sync. Run terraform import or delete the resource in Atlas UI, then re-run apply.

💡 How to ignore specific resources?

Add lifecycle { ignore_changes = [tags] } to the resource block. Useful for auto-generated cloud metadata.
