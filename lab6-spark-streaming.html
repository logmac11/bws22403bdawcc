📦 Step 1: Environment Setup

We will use a **TCP Socket** to simulate a live data feed. This requires running a producer script in one cell and the Spark consumer in another.

!pip install pyspark import subprocess import threading import random import time import json # Start a background socket server simulating CampusMart orders def producer(): import socket server = socket.socket(socket.AF_INET, socket.SOCK_STREAM) server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1) server.bind(('localhost', 9999)) server.listen(1) print("📡 Producer listening on port 9999...") conn, _ = server.accept() categories = ["Textbooks", "Electronics", "Appliances"] try: while True: record = { "category": random.choice(categories), "price": round(random.uniform(10, 200), 2), "event_time": time.strftime("%Y-%m-%d %H:%M:%S") } conn.send((json.dumps(record) + "\n").encode()) time.sleep(1) except: pass finally: conn.close() threading.Thread(target=producer, daemon=True).start() print("✅ Producer thread started.")

⚡ Step 2: Read & Parse Stream

Spark Structured Streaming treats the socket as an unbounded table.

from pyspark.sql import SparkSession from pyspark.sql.functions import from_json, col from pyspark.sql.types import StructType, StringType, DoubleType spark = SparkSession.builder.appName("Lab6-Streaming").getOrCreate() # Define schema matching JSON records schema = StructType() \ .add("category", StringType()) \ .add("price", DoubleType()) \ .add("event_time", StringType()) # Read stream raw_stream = spark.readStream \ .format("socket") \ .option("host", "localhost") \ .option("port", 9999) \ .load() # Parse JSON parsed_stream = raw_stream.select(from_json(col("value"), schema).alias("data")).select("data.*") # Query 1: Console output query = parsed_stream.writeStream \ .outputMode("append") \ .format("console") \ .start() # Let it run for 10 seconds then stop time.sleep(10) query.stop()
🔍 Key Concepts:
  • readStream vs read: Defines a streaming DataFrame
  • outputMode("append"): Only new rows are written
  • writeStream.start(): Triggers continuous execution
  • Spark processes data in micro-batches (default 500ms)

📈 Step 3: Windowed Aggregations

Analyze metrics over sliding time windows (e.g., "Revenue per 5-minute window").

from pyspark.sql.functions import window, sum as spark_sum # Windowed query windowed_agg = parsed_stream \ .groupBy(window(col("event_time"), "5 minutes")) \ .agg(spark_sum("price").alias("total_revenue")) query2 = windowed_agg.writeStream \ .outputMode("complete") \ .format("console") \ .option("truncate", "false") \ .start() time.sleep(15) query2.stop()
✅ Expected Console Output:
------------------------------------------- | window | total_revenue | ------------------------------------------- | [2026-04-16 10:00, ...)| 450.50 | | [2026-04-16 10:05, ...)| 120.00 | -------------------------------------------

💧 Step 4: Watermarking (Handling Late Data)

In real systems, data arrives late. Watermarks tell Spark when to drop old state and stop waiting for late records.

# Cast to Timestamp & Apply Watermark timestamped_stream = parsed_stream.withColumn("ts", col("event_time").cast("timestamp")) watermarked_query = timestamped_stream \ .withWatermark("ts", "10 minutes") \ .groupBy(window(col("ts"), "5 minutes"), "category") \ .agg(spark_sum("price").alias("revenue")) query3 = watermarked_query.writeStream \ .outputMode("complete") \ .format("console") \ .start() time.sleep(20) query3.stop()
🔍 Watermark Logic:
  • withWatermark("ts", "10 min"): Drop state older than 10 min relative to max event time
  • Prevents memory leaks in infinite streams
  • Essential for production reliability

🛠️ Troubleshooting & Tips

❌ "Connection refused" to socket

Ensure the producer thread is running before starting the Spark query. In Colab, run the producer cell first, wait for "Listening...", then run Spark cell.

❌ "Watermarking not supported in append mode with joins"

Watermarks in Append mode only work with simple aggregations. For joins or complex state, use outputMode("update") or "complete".

💡 How to stop a stuck query?

In Colab, click the Stop button (square icon) in the cell toolbar. In local Spark, use query.stop() or kill the driver process.
