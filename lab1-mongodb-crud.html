📦 What is CampusMart?

🗂️ Document Structure Explained

MongoDB stores data as flexible BSON documents (Binary JSON). Unlike SQL tables with fixed columns, each document can have different fields:

{ "_id": ObjectId("67890abcdef1234567890"), "name": "Calculus Early Transcendentals", "category": "Textbooks", "price": 45.00, "currency": "MYR", "seller": { "name": "Ahmad", "matric": "AD200001", "rating": 4.8 }, "tags": ["mathematics", "semester1", "hardcover"], "specs": { "edition": "8th", "year": 2022, "pages": 1344 }, "inStock": true, "listedDate": ISODate("2026-04-10T08:30:00Z") }
🔍 Key Concepts:
  • _id: Auto-generated unique identifier
  • Embedded Documents: seller and specs are nested objects (no SQL JOIN needed!)
  • Arrays: tags can hold multiple values
  • Flexible Schema: Different products can have different fields

🐳 Step 1: Start MongoDB Container

⚠️
Prerequisite: Ensure Docker Desktop is installed and running (green dot: "Engine running").

We'll run MongoDB locally using Docker. This mirrors how cloud platforms provision database instances.

1 Open PowerShell or Terminal
Ensure Docker Desktop is running before proceeding.
2 Run the MongoDB Container
docker run -d ` --name uthm-mongo-lab ` -p 27017:27017 ` -e MONGO_INITDB_ROOT_USERNAME=student ` -e MONGO_INITDB_ROOT_PASSWORD=uthm2026 ` --memory="1g" ` mongo:7.0
🔧 What Each Flag Does:
  • -d → Run in detached mode (background)
  • --name uthm-mongo-lab → Container identifier
  • -p 27017:27017 → Map host port to container port
  • -e MONGO_INITDB_ROOT_USERNAME/PASSWORD → Set admin credentials
  • --memory="1g" → Limit RAM usage (protects slower laptops)
  • mongo:7.0 → Use MongoDB version 7.0
💡 Windows Single-Line Version (if backticks fail):
docker run -d --name uthm-mongo-lab -p 27017:27017 -e MONGO_INITDB_ROOT_USERNAME=student -e MONGO_INITDB_ROOT_PASSWORD=uthm2026 --memory="1g" mongo:7.0
3 Verify It's Running
docker ps
✅ Expected Output:
CONTAINER ID IMAGE COMMAND STATUS PORTS NAMES a1b2c3d4e5f6 mongo:7.0 "docker-entrypoint.s…" Up 2 minutes 0.0.0.0:27017->27017/tcp uthm-mongo-lab

🔄 Step 2: Container Management (Remove & Reuse)

📚
Why This Matters: In real development, you'll frequently need to restart, stop, or recreate containers. Understanding container lifecycle management is essential for DevOps and cloud engineering.

🔍 When to Reuse vs. Remove

SituationActionCommand
Container exists with correct configReuse (just start it)docker start uthm-mongo-lab
Container stopped but config is goodRestartdocker restart uthm-mongo-lab
Wrong password/configRemove & recreatedocker rm -f uthm-mongo-lab then docker run...
Need fresh databaseRemove & recreatedocker rm -f uthm-mongo-lab then docker run...

📌 Task 1: Check Existing Containers

# See running containers docker ps # See ALL containers (including stopped) docker ps -a
✅ What to Look For:
  • STATUS = "Up" → Container is running
  • STATUS = "Exited" → Container is stopped but exists
  • No output → No containers exist yet

📌 Task 2: Reuse an Existing Container

If docker ps -a shows uthm-mongo-lab, you can reuse it:

# Start a stopped container docker start uthm-mongo-lab # Or restart (stop then start) docker restart uthm-mongo-lab # Verify it's running docker ps
💡 Pro Tip: Reusing containers preserves your data! If you inserted documents in Lab 1, they'll still be there when you restart the container.

📌 Task 3: Remove and Recreate (When Needed)

If you get "Error: container name already in use" or need to change the password:

# Force remove container (even if running) docker rm -f uthm-mongo-lab # Verify it's gone docker ps -a # Now create fresh container docker run -d --name uthm-mongo-lab -p 27017:27017 -e MONGO_INITDB_ROOT_USERNAME=student -e MONGO_INITDB_ROOT_PASSWORD=uthm2026 --memory="1g" mongo:7.0
⚠️
Warning: docker rm -f deletes all data in the container! Only use this when you need a fresh start or when configuration is wrong.

📌 Task 4: Inspect Container Configuration

To check what password/environment variables a container has:

docker inspect uthm-mongo-lab | findstr MONGO_INITDB
✅ Expected Output:
"MONGO_INITDB_ROOT_USERNAME=student", "MONGO_INITDB_ROOT_PASSWORD=uthm2026",

🔌 Step 3: Connect to MongoDB

Connect using mongosh (CLI) or Compass (GUI). Both work identically for CRUD operations.

🖥️ Option A: MongoDB Shell (mongosh)

1 Open a NEW terminal window (keep Docker terminal open)
mongosh "mongodb://student:uthm2026@localhost:27017/admin"
🔍 Connection String Breakdown:
  • mongodb:// → Protocol
  • student:uthm2026 → Username:Password
  • @localhost:27017 → Host & Port
  • /admin → Authentication database

🖼️ Option B: MongoDB Compass (GUI)

1 Open Compass → Paste: mongodb://student:uthm2026@localhost:27017/ → Click Connect

📝 Step 4: CRUD Operations (Hands-On)

Practice Create, Read, Update, Delete using realistic CampusMart data.

✅ CREATE: Insert Products

use campusmart db.products.insertOne({ name: "Python Crash Course", category: "Textbooks", price: 55.00, currency: "MYR", seller: { name: "Siti", matric: "AD200002", rating: 4.9 }, tags: ["programming", "python", "beginner"], specs: { edition: "3rd", year: 2023, pages: 544 }, inStock: true, listedDate: new Date("2026-04-15") })
🔍 Command Breakdown:
  • db.products → References the "products" collection
  • insertOne({...}) → Inserts a single document
  • seller: {...} → Embedded document (nested object)
  • new Date(...) → Creates ISODate timestamp
✅ Expected: { acknowledged: true, insertedId: ObjectId("...") }

📖 READ: Query Data

db.products.find({ category: "Textbooks" }) db.products.find( { category: "Textbooks" }, { name: 1, price: 1, "seller.rating": 1, _id: 0 } )

🔄 UPDATE: Modify Records

db.products.updateOne( { name: "Dorm Mini Fridge" }, { $set: { price: 220.00, inStock: true } } ) db.products.updateOne( { name: "Python Crash Course" }, { $addToSet: { tags: "data_science" } } )

🗑️ DELETE: Remove Records

db.products.deleteOne({ name: "Logitech MX Master 3S" }) db.products.countDocuments()

🔍 Step 6: Query & Analyze

Practice queries that simulate real analytics tasks.

📊 Task 1: Filter & Sort

Find all in-stock textbooks under RM 60, sorted by price:

db.products.find( { category: "Textbooks", inStock: true, price: { $lt: 60 } }, { name: 1, price: 1, _id: 0 } ).sort({ price: 1 })

📈 Task 2: Array Matching

Find products tagged with "dorm" OR "math":

db.products.find( { tags: { $in: ["dorm", "math"] } }, { name: 1, tags: 1, _id: 0 } )

👤 Task 3: Nested Document Query

Find products sold by sellers with rating ≥ 4.8:

db.products.find( { "seller.rating": { $gte: 4.8 } }, { name: 1, "seller.name": 1, "seller.rating": 1, _id: 0 } )
🎯
Analytics Bridge: These query patterns form the foundation for Week 2's Aggregation Pipeline ($match, $group, $sort) and Week 6's PySpark integration.

🛠️ Troubleshooting & Tips

❌ "Port 27017 already in use"

Another MongoDB instance is running. Stop it:

# Windows: net stop MongoDB # macOS: brew services stop mongodb-community # Linux: sudo systemctl stop mongod
❌ "Connection refused" in mongosh/Compass

Container isn't running. Check with docker ps. If missing, restart with the docker run command from Step 1.

❌ mongoimport: command not found

See Lab 0 Step 4. Add MongoDB Tools to PATH or use Compass GUI import: Collections → "+" → Import File → JSON.

💡 How to stop/clean up after lab?
# Stop container docker stop uthm-mongo-lab # Start again later docker start uthm-mongo-lab # Complete reset (deletes all data) docker rm -f uthm-mongo-lab
