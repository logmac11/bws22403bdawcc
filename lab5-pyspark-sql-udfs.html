🔍 Step 2: Spark SQL Queries

Spark SQL lets analysts write familiar SQL while Spark handles distributed execution.

# SQL: Category revenue & stock status spark.sql(""" SELECT category, COUNT(*) as product_count, AVG(price) as avg_price, SUM(CASE WHEN inStock THEN 1 ELSE 0 END) as in_stock_count FROM products GROUP BY category ORDER BY avg_price DESC """).show()
🔍 Why Spark SQL?
  • Declarative syntax → Spark optimizes execution plan automatically
  • Easy for BI analysts to transition from MySQL/PostgreSQL
  • Temp views don't store data; they're just logical references

🛠️ Step 3: Custom UDFs (User-Defined Functions)

UDFs let you apply Python functions to distributed columns. Use sparingly—built-in functions are faster.

from pyspark.sql.functions import udf from pyspark.sql.types import StringType # Business rule: Classify product pricing tier def price_tier(price): if price is None: return "Unknown" if price < 50: return "Budget" elif price < 150: return "Mid-Range" else: return "Premium" # Register UDF tier_udf = udf(price_tier, StringType()) # Apply to DataFrame df_with_tier = df.withColumn("price_tier", tier_udf(df.price)) df_with_tier.groupBy("price_tier").count().show()
⚠️
Performance Note: UDFs run as black boxes in Python, bypassing Spark's Catalyst optimizer. Prefer built-in functions like when(), expr(), or pandas_udf (Arrow-optimized) for production.

📈 Step 4: Window Functions for Rankings

Window functions compute across rows related to the current row, without collapsing the result set.

from pyspark.sql.window import Window from pyspark.sql.functions import rank, col # Rank products by price within each category window_spec = Window.partitionBy("category").orderBy(col("price").desc()) df.withColumn("price_rank", rank().over(window_spec)) \ .filter(col("price_rank") <= 2) \ .select("category", "name", "price", "price_rank") \ .orderBy("category", "price_rank") \ .show()
🔍 Window vs GroupBy:
  • groupBy() → collapses rows into aggregates
  • Window() → keeps original rows, adds computed columns
  • Essential for "top N per group", running totals, % of total

⚡ Step 5: Caching & Performance Comparison

Cache frequently accessed DataFrames in memory to avoid recomputation.

import time # Without cache start = time.time() df.filter(col("category") == "Textbooks").count() print(f"Uncached: {time.time() - start:.3f}s") # With cache df.cache() start = time.time() df.filter(col("category") == "Textbooks").count() print(f"Cached: {time.time() - start:.3f}s") df.unpersist() # Free memory
✅ Expected: Cached execution is significantly faster (often 2–10x) because Spark skips recomputing the lineage.

🛠️ Troubleshooting & Tips

❌ "UDF is slower than expected"

Replace Python UDF with Spark SQL when().otherwise() or pandas_udf (Arrow vectorized execution). UDFs break Catalyst optimization.

❌ "Window function returns wrong ranks"

Ensure orderBy() matches your ranking logic. Use rank() for ties, row_number() for strict ordering, or dense_rank() to avoid rank gaps.

❌ "Cache doesn't speed up query"

Small datasets fit in memory instantly. Test with larger partitions or use df.count() to force materialization before timing. Always call unpersist() afterward.
